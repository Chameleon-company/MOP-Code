Background

Applying for jobs is often inefficient and time-consuming. Candidates frequently apply to roles that do not align well with their skills or experience, leading to low response rates and wasted effort.

The problem is not a lack of opportunities — it is a lack of clarity on job-fit. Most candidates rely on manual judgment or keyword matching, which fails when job descriptions use different wording or when the relevance is not obvious.

There is currently no simple system that can quantify how well a resume matches a job description while also explaining why.

ResumeMatch addresses this by combining multiple Natural Language Processing (NLP) techniques to evaluate job-fit in a more structured and interpretable way.

Use Case

Component Detail
Product A Resume-to-Job Matching Assistant that generates a Job Fit Score based on resume and job description alignment
Primary Actors Job seekers, students, early-career professionals
Secondary Actors Recruiters, career advisors, hiring teams
Scenario A candidate wants to quickly determine whether a job is worth applying to based on how well their resume matches the job requirements
Goal Provide a clear job-fit score along with matched and missing skills to support better application decisions

User Stories

  • As a job seeker, I want to know how well my resume matches a job description, so that I can focus on applying to roles where I have a higher chance of success.

  • As a student or graduate, I want to identify missing skills in job descriptions, so that I can improve my resume and better align with industry expectations.

  • As a career advisor, I want a tool that can explain why a resume is a strong or weak match for a job, so that I can guide candidates more effectively.

Techniques Used

# Method Role in ResumeMatch
1 TF-IDF + Cosine Similarity Measures keyword-based relevance between resume and job description
2 Semantic Similarity (Sentence Embeddings) Captures contextual meaning and related concepts beyond exact keywords
3 Skill Extraction Identifies technical skills present in resume and job description
4 Skill Gap Analysis Highlights matched and missing skills
5 Hybrid Scoring Model Combines multiple signals into a final Job Fit Score

Workflow

  • Environment Setup & Data Input — Load resume and job description (text or PDF)
  • Text Preprocessing — Clean and normalize text for analysis
  • Baseline Matching (TF-IDF) — Compute keyword similarity score
  • Skill Extraction & Gap Analysis — Identify matched and missing skills
  • Semantic Similarity (Advanced Stage) — Compute contextual similarity using embeddings
  • Model Comparison — Compare TF-IDF vs semantic results
  • Final Scoring Model — Combine all signals into a Job Fit Score
  • UI Application (Streamlit) — Allow users to upload resume and evaluate job-fit interactively

3) Text Preprocessing

Normalize text by lowercasing, removing punctuation, tokenizing, and dropping stopwords.

nltk.download("punkt")
nltk.download("stopwords")

stop_words = set(stopwords.words("english"))

def preprocess_text(text):
    text = text.lower()
    text = text.translate(str.maketrans("", "", string.punctuation))
    text = re.sub(r"\s+", " ", text).strip()
    tokens = word_tokenize(text)
    cleaned_tokens = [word for word in tokens if word.isalpha() and word not in stop_words]
    return " ".join(cleaned_tokens)
cleaned_resume_text = preprocess_text(resume_text)
jobs_df["cleaned_description"] = jobs_df["description"].apply(preprocess_text)
cleaned_job_texts = jobs_df["cleaned_description"].tolist()

4) Text Similarity Matching

Use TF-IDF vectors and cosine similarity to score each job against the resume.

all_documents = [cleaned_resume_text] + cleaned_job_texts

5) Skill Extraction and Overlap

Extract known skills from both resume and jobs, then compute matched and missing skills.

Note: Skill extraction is based on direct string matching and may fail for synonyms or variations in wording

skill_list = [
    "python", "sql", "excel", "tableau", "power bi", "machine learning",
    "deep learning", "data analysis", "data visualization", "nlp",
    "computer vision", "opencv", "yolo", "pandas", "numpy",
    "scikit-learn", "tensorflow", "pytorch", "git", "aws",
    "feature engineering", "model evaluation", "dashboard", "reporting",
    "statistics", "data preprocessing", "business intelligence"
]

def extract_skills(text, skills):
    text = text.lower()
    return sorted({skill for skill in skills if skill in text})

def compare_skills(resume_skills, job_skills):
    matched = sorted(set(resume_skills).intersection(set(job_skills)))
    missing = sorted(set(job_skills) - set(resume_skills))
    return matched, missing

def skill_overlap_score(job_skills, matched_skills):
    return 0 if not job_skills else len(matched_skills) / len(job_skills)
resume_skills = extract_skills(cleaned_resume_text, skill_list)
jobs_df["job_skills"] = jobs_df["cleaned_description"].apply(lambda x: extract_skills(x, skill_list))

jobs_df[["matched_skills", "missing_skills"]] = jobs_df.apply(
    lambda row: pd.Series(compare_skills(resume_skills, row["job_skills"])), axis=1
)

jobs_df["skill_overlap_score"] = (
    jobs_df.apply(lambda row: skill_overlap_score(row["job_skills"], row["matched_skills"]), axis=1) * 100
).round(2)

jobs_df[["title", "matched_skills", "missing_skills", "skill_overlap_score"]].head()

Scoring Strategy Justification (Phase 1: Baseline)

The prototype score combines text similarity (70%) and skill overlap (30%). Text similarity is weighted higher because TF-IDF captures overall alignment between the resume and job description. Skill overlap (30%) provides interpretability by highlighting specific matching and missing skills.

Note: These weights are heuristic and not learned from data. They are chosen to balance global text similarity with explicit skill matching. In future iterations, these weights could be tuned using real hiring data.

8) Semantic Similarity Analysis

This phase extends the baseline model by introducing semantic understanding through pre-trained embeddings. Unlike keyword-based methods, semantic similarity captures contextual meaning and conceptual relationships between the resume and job descriptions.

from sentence_transformers import SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity

# Load pre-trained semantic embedding model
model = SentenceTransformer('all-MiniLM-L6-v2')
print("Semantic embedding model loaded: all-MiniLM-L6-v2")
# Extract original raw text (not preprocessed) for semantic encoding
# Raw text preserves context better than cleaned text for embedding models
resume_raw = resume_text
job_raw_list = jobs_df['description'].tolist()

# Encode resume and all job descriptions using semantic embeddings
print("Encoding resume...")
resume_embedding = model.encode([resume_raw])

print("Encoding job descriptions...")
job_embeddings = model.encode(job_raw_list)

print(f"Resume embedding shape: {resume_embedding.shape}")
print(f"Job embeddings shape: {job_embeddings.shape}")
# Calculate semantic similarity scores using cosine similarity
semantic_scores = cosine_similarity(resume_embedding, job_embeddings)[0]
jobs_df['semantic_similarity'] = semantic_scores
jobs_df['semantic_match_percentage'] = (semantic_scores * 100).round(2)

Hybrid Model: Weight Selection Rationale

The final scoring model combines three complementary signals:

Semantic Similarity (50%)

  • Why highest weight: Captures contextual meaning and conceptual alignment beyond exact keywords
  • Identifies roles with similar responsibilities and skills even when expressed differently
  • Reduces false negatives from keyword-based approaches

Skill Overlap (30%)

  • Why moderate weight: Provides explicit, interpretable evidence of capability matching
  • Identifies specific required skills that are present or missing in the candidate profile
  • Prevents over-reliance on semantic similarity which may overestimate alignment

TF-IDF Similarity (20%)

  • Why lowest weight: Serves as a precision stabilizer
  • Ensures presence of specific job domain keywords (e.g., "Machine Learning", "SQL")
  • Prevents semantic similarity from generating false matches on broadly similar content

Design Philosophy

This weighting reflects a balanced approach: meaning > skills > keywords. In practice, how a job is described matters most, but explicit skill requirements and technical terminology act as important guardrails.

Model Evaluation & Interpretation

Results Summary

The hybrid ranking produces meaningful prioritization:

  • Top-ranked roles combine high semantic alignment with strong skill overlap (e.g., ML Intern, Data Scientist)
  • Mid-ranked roles may have good semantic fit but lower skill coverage (e.g., Data Analyst)
  • Lower-ranked roles show weak alignment in multiple dimensions

Key Observations

Stability: Top 3 rankings remain consistent across all three methods, indicating genuine strong matches rather than method-specific artifacts.

Skill Impact: The skill overlap component successfully prevents high semantic scores from overriding missing critical technical requirements.

Differentiation: Many jobs cluster in the 40-60% range, suggesting that job descriptions vary significantly in their alignment with the candidate profile.

Method Comparison

  • TF-IDF alone: Biased toward exact keyword matches; misses jobs using different terminology
  • Semantic alone: Can overestimate alignment due to general domain similarity without technical depth
  • Hybrid model: Balances all three signals, producing rankings that account for meaning, skills, and keywords

Limitations & Future Improvements

Current Limitations

Scoring Weights: The 50/30/20 split is heuristic, not learned from real hiring data. Ideally, weights should be calibrated using historical hiring outcomes.

Skill List Completeness: The skill extractor depends on a predefined list. It will miss:

  • Domain-specific variations and synonyms (e.g., "deep neural networks" vs "deep learning")
  • Industry-specific terminology
  • Emerging technologies not in the original list

Semantic Model Boundaries: Pre-trained embeddings may overestimate relevance when:

  • Job descriptions are in different domains (e.g., finance vs healthcare)
  • Technical depth varies significantly

Resume-Job Mismatch: The system ranks based on match, but doesn't account for:

  • Seniority alignment (entry-level candidate vs senior role)
  • Experience depth (breadth vs. specialized expertise)
  • Company culture fit or growth opportunity

Potential Enhancements

  1. Weight Tuning: Train weights on labeled hiring data (matches vs. non-matches)
  2. Skill Expansion: Dynamically extract skills using NER (Named Entity Recognition) instead of static lists
  3. Context Awareness: Weight skill overlap differently based on required vs. nice-to-have skills
  4. Seniority Detection: Add role-level matching (junior, mid, senior positions)
  5. Explainability: Generate detailed explanations for each ranking decision

Technical Reflection & Conclusions

Journey Through Approaches

Phase 1 - Baseline (TF-IDF):

  • Simple and fast, but purely lexical
  • Fails when job descriptions use different terminology for the same concept
  • Provides baseline interpretability through term importance

Phase 2 - Semantic Enhancement:

  • Captures conceptual similarity independent of exact wording
  • More robust to paraphrasing and synonyms
  • Risk: Over-generalizes (high semantic match ≠ technical fit)

Phase 3 - Hybrid Integration:

  • Combines precision (TF-IDF), meaning (Semantic), and explainability (Skills)
  • Demonstrated that no single approach dominates; each adds value
  • Produced rankings that align with intuitive expectations about role fit

Key Engineering Insights

  1. Signal Complementarity: When three independent signals are combined thoughtfully, the result is more robust than any single method

  2. Weight Ratios Matter: The 50/30/20 split reflects a belief about what matters most in job matching (meaning > skills > keywords). This belief should be validated against real data.

  3. Interpretability is Critical: By including skill overlap scoring, we gain the ability to explain why a job ranked highly (or poorly), not just report a number.

Recommended Next Steps

For production deployment, this system should:

  • Collect feedback on ranking quality to calibrate weights
  • Integrate with recruiter feedback loops
  • Track conversion rates (matches → applications → interviews → offers)
  • Expand skill databases periodically
