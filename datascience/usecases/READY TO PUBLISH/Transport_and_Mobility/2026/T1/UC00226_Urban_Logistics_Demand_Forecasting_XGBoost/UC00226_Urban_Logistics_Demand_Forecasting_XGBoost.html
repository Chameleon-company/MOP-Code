Scenario

The city transport authority wants to optimise delivery routes and reduce congestion in urban areas. They have collected data from traffic sensors counting vehicles, specifically vans and trucks, at various locations across the city from 2023 to 2026.

By pinpointing periods of highest logistics demand and analysing trends over time, city authorities can make informed decisions regarding freight management, infrastructure development, and traffic regulation. Such understanding also supports optimised delivery scheduling and more efficient urban logistics operations throughout Melbourne.

User Story

As a city logistics planner, I want to analyse van and truck traffic across key locations and times, So that I can identify peak periods of activity and forecast future demand also reduce congestion, improve delivery efficiency. This insight will enable better planning of freight movement, transport infrastructure, and overall urban logistics operations.

Introduction

This document aims to explore urban logistics demand patterns in Melbourne by analysing van and truck traffic across the city over multiple years.

This analysis follows these main stages:

Data Collection – Importing traffic count datasets for vans and trucks from 2023 to 2026, including information on location, time, and vehicle counts.

Data Cleaning & Preprocessing – Renaming columns for clarity, filtering for relevant vehicle types (vans and trucks), converting timestamps to datetime format, and extracting time-based features such as hour, day, and year.

Exploratory Data Analysis (EDA) – Summarising and visualising logistics activity trends over time, identifying peak traffic hours, busiest days of the week, and top traffic locations.

Aggregation & Trend Analysis – Grouping data by year, location, and other relevant dimensions to observe growth patterns and hotspots in urban freight movement.

Visual Analysis – Using line charts, bar charts, and histograms to present traffic patterns and insights in an easily interpretable way.

The outcome of this work can assist city transport planners, logistics operators, and policy-makers in making data-driven decisions to optimise urban freight operations, reduce congestion, and plan for future infrastructure development.

Dataset Links Transport Activity Counts - https://data.melbourne.vic.gov.au/explore/dataset/transport-activity-counts/api/

Data Extraction

In this step, we import necessary libraries and load van and truck traffic datasets for Melbourne from 2023 to 2026. The datasets are provided as ZIP files containing CSV files. The dataset is accessible through a public API, retrieving historical records directly via the API was not available, as the endpoint currently returns no records. Therefore, the historical datasets were downloaded as ZIP files from the Melbourne Open Data Portal for years 2023,2024,2025,2026 and uploaded to the Github repositories in dependencies folder.

Each ZIP archive contains transport activity data for multiple years, with each year stored in a separate dataset file. For this analysis, four years of historical data were extracted and combined to study transport activity trends over time.

Since direct datasets measuring urban freight or logistics demand are not publicly available, transport activity data serves as a proxy. Higher traffic counts likely correspond to increased movement of vans and trucks, which can indicate higher logistics and delivery activity across Melbourne’s road network.

The workflow includes:

  1. Define URLs for transport activity ZIP files (2023–2026).
  2. Download each ZIP file using requests.
  3. Read ZIP files in memory using zipfile.
  4. Extract and load all CSV files into Pandas DataFrames.
  5. Store all DataFrames in a list.
  6. Combine all datasets into a single DataFrame using pd.concat().
  7. Preview the final dataset using shape and head.

This consolidated dataset will serve as the foundation for cleaning, exploration, and visualisation of urban logistics demand patterns.

Feature Engineering for Time Series Forecasting¶

In this step, the dataset is prepared for time series forecasting by aggregating vehicle counts, generating temporal features, and creating lag-based statistics. These engineered features help the model capture traffic trends, seasonality, and temporal dependencies across different locations.

1. Data Aggregation and Sorting¶

The raw vehicle data is first grouped by:

  • start_time
  • location_id
  • latitude
  • longitude

The vehicle_count values are summed for each combination to obtain the total number of vehicles observed at a specific location and time.

After aggregation, the dataset is sorted by:

  1. location_id
  2. start_time

Sorting is critical before generating lag features because time series models require observations to be in chronological order within each location.

2. Time-Based Feature Extraction¶

Several temporal features are extracted from the start_time column to help the model learn recurring traffic patterns:

  • hour - captures hourly traffic variations
  • day - captures daily trends within a month
  • month - captures seasonal effects
  • year - captures yearly variations
  • dayofweek - identifies weekday vs. weekend behavior
  • is_weekend - binary feature indicating weekends (1) or weekdays (0)

These features allow the forecasting model to detect cyclic traffic patterns such as rush hours and weekend fluctuations.

3. Lag Features¶

Lag features provide historical context by including previous observations of vehicle counts for the same location.

  • lag_1 - vehicle count from the previous hour
  • lag_24 - vehicle count from the same hour on the previous day

These features are especially useful in time series forecasting because traffic patterns often depend heavily on recent observations.

The groupby("location_id") operation ensures that lag calculations remain isolated within each location, preventing data leakage across different geographic areas.

4. Rolling Mean Features¶

Rolling averages are used to smooth short-term fluctuations and capture broader traffic trends.

  • rolling_mean_3 - average vehicle count over the previous 3 time steps
  • rolling_mean_24 - average vehicle count over the previous 24 time steps

The rolling calculations are shifted by one step to ensure that only past information is used when predicting future values.

5. Handling Missing Values¶

Lag and rolling operations naturally create missing values at the beginning of each location’s time series. These rows are removed using dropna() to ensure the final dataset contains only complete feature sets suitable for model training.

Finally, the dataset shape and sample rows are displayed to verify successful feature engineering.

import pandas as pd
import numpy as np

# ── 1. Sort globally by time first (critical before lag features) ──────────
forecast_df = (
    van_truck_df
    .groupby(["start_time", "location_id", "latitude", "longitude"], as_index=False)["vehicle_count"]
    .sum()
    .sort_values(["location_id", "start_time"])   # sort within each location
    .reset_index(drop=True)
)

# ── 2. Time features ──────────────────────────────────────────────────────
forecast_df["hour"]      = forecast_df["start_time"].dt.hour
forecast_df["day"]       = forecast_df["start_time"].dt.day
forecast_df["month"]     = forecast_df["start_time"].dt.month

forecast_df["is_weekend"] = forecast_df["dayofweek"].isin([5, 6]).astype(int)

# ── 3. Lag & rolling features (FIXED: transform keeps group boundaries) ───
forecast_df["lag_1"] = (
    forecast_df.groupby("location_id")["vehicle_count"]
    .transform(lambda x: x.shift(1))
)
forecast_df["lag_24"] = (
    forecast_df.groupby("location_id")["vehicle_count"]
    .transform(lambda x: x.shift(24))          # same hour, previous day
)
forecast_df["rolling_mean_3"] = (
    forecast_df.groupby("location_id")["vehicle_count"]
    .transform(lambda x: x.shift(1).rolling(3, min_periods=1).mean())
)
forecast_df["rolling_mean_24"] = (
    forecast_df.groupby("location_id")["vehicle_count"]
    .transform(lambda x: x.shift(1).rolling(24, min_periods=1).mean())
)

Model Evaluation Metrics¶

A custom evaluation function is defined to measure the performance of forecasting models using multiple regression metrics.

The following metrics are calculated:

  • MAE (Mean Absolute Error): Measures the average absolute difference between actual and predicted vehicle counts.
  • RMSE (Root Mean Squared Error): Penalises larger prediction errors and indicates overall prediction accuracy.
  • R² Score: Represents how well the model explains the variability in vehicle counts.
  • MAPE (Mean Absolute Percentage Error): Measures prediction error as a percentage, making results easier to interpret.

The function prints the evaluation results in a structured format and returns the metrics as a dictionary for further comparison across models.

In [ ]:
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

def evaluate(name, y_true, y_pred):
    mae  = mean_absolute_error(y_true, y_pred)
    rmse = np.sqrt(mean_squared_error(y_true, y_pred))
    r2   = r2_score(y_true, y_pred)
    mape = np.mean(np.abs((y_true - y_pred) / (y_true.clip(lower=1)))) * 100

    print(f"\n{'='*45}")
    print(f"  {name}")
    print(f"{'='*45}")
    print(f"  MAE  : {mae:.3f}  vehicles")
    print(f"  RMSE : {rmse:.3f}  vehicles")
    print(f"  R²   : {r2:.4f}  ")
    print(f"  MAPE : {mape:.2f}%")
    return {"model": name, "MAE": mae, "RMSE": rmse, "R2": r2, "MAPE": mape}

After training, predictions are generated on the test dataset and evaluated using the predefined performance metrics.

Future Demand Forecasting¶

The trained XGBoost model is used to generate a 24-hour vehicle demand forecast for each location.

The forecasting process begins by selecting the most recent observation for every location_id as the starting point. Future timestamps are then created hour-by-hour for the next 24 hours.

For each future time step:

  • Temporal features such as hour, day, month, and weekend indicators are generated
  • Previously known lag and rolling statistics are carried forward as approximate historical inputs

The model predicts future vehicle counts using these generated features, and negative predictions are clipped to zero to maintain realistic values.

Finally:

  • A sample of forecasted results is displayed
  • A time series plot is created to visualise the predicted vehicle demand over the next 24 hours for a selected location

This step demonstrates how the trained forecasting model can be applied for short-term future demand prediction.

In [ ]:
from datetime import timedelta

# Use the last known row per location as the seed
last_known = (
    forecast_df.sort_values("start_time")
    .groupby("location_id")
    .last()
    .reset_index()
)

future_rows = []
for _, row in last_known.iterrows():
    for h in range(1, 25):   # forecast 24 hours ahead
        future_time = row["start_time"] + timedelta(hours=h)
        future_rows.append({
            "location_id":    row["location_id"],
            "latitude":       row["latitude"],
            "longitude":      row["longitude"],
            "start_time":     future_time,
            "hour":           future_time.hour,
            "day":            future_time.day,
            "month":          future_time.month,
            "year":           future_time.year,
            "dayofweek":      future_time.weekday(),
            "is_weekend":     int(future_time.weekday() >= 5),
            # carry forward last known lag values as approximation
            "lag_1":          row["vehicle_count"],

Recommendations:

CONCLUSION — Urban Logistics Demand Forecasting

This use case demonstrated how publicly available transport activity data can be leveraged to understand and forecast urban logistics demand across Melbourne. By analysing van and truck traffic patterns from 2023 to 2026, we identified clear peak delivery periods, high-demand locations, and seasonal trends. Through structured feature engineering and an XGBoost forecasting model, we achieved significantly better predictions than the naive baseline, with lag features and time-based signals proving to be the strongest drivers of demand. The resulting 24-hour forecasts provide city planners and logistics operators with actionable, data-driven insights to optimise delivery scheduling, manage congestion, and plan freight infrastructure more effectively
